01 — /ship

一句话到落地。

两次确认。此后自主。

  1. Grill

    设计树访谈。事实自己查；每轮问当前 frontier，并给出推荐答案。

  2. Spec — 关口 1

    自动合成。你确认。每条标准写明证明它的命令。

  3. Tickets — 关口 2

    自动切成可独立验证的垂直切片。你批准。写代码前先跑基线。

  4. 落地

    在 spec 记下的 seam 上 TDD。每个变绿的 ticket 提交一次。

  5. 完成

    每条标准重跑并汇报。

01 — 看一眼

下面每一个终端都是真的。

从打包后的二进制抓取。不是效果图。

备用屏幕、钉在底部从不移动的输入框，以及始终当前的状态行。

刚提交的问题占住视口顶部，回复从下方填进空出来的位置。往回读历史再回到底部，回来的是同一帧——滚轮和 PgDn 都能落回去。

往回滚过一次轮次边界，问出这几行的那条提问就钉在顶部；右侧一列时间线标出当前在哪一轮，Shift+←/→ 在轮次之间跳。

每次调用都经由它的 presenter 渲染——标题、状态、diff——左侧还有一道标出块边界的竖线。

点一下展开落点那一块，在块内任意处再点一下收起；Ctrl+O 依然一次开合全部，手动开合的选择会跨轮次保留。

一行常驻读数把 agent 的清单钉在状态行之上，不随那次写入滚走；Ctrl+T 展开为完整清单。

表格排出真正的列，代码带高亮，强调标记被吃掉而不是打印出来。

/view 1 打开一条回答，/view 1:1 打开它的第一个代码块，改窗口大小也不会乱；Esc 原样还回会话。/copy 用的是同一套编号。

Shift+←/→

在真实轮次之间跳；/jump 预览一轮，Esc 原样还回。

/copy

/copy N 取一条回答的原始 Markdown，/copy N:C 取它的代码，不含围栏。

Ctrl+V

粘贴图片：原生视觉，或由 DeepSeek 文本模型借用 Vision Exp 描述一次。

/ $ ! @

命令、skill、shell、文件——菜单在输入框上方开。⇧Tab 是 plan 模式。

拖选

选中即复制，走 OSC 52 或系统剪贴板。

管道

非 TTY 是降级不是崩：行读取器，无组件、不绘制。

02 — 安装与运行

两个包，一份 dsh。

零依赖启动器。codsh 即 dsh --profile code。

codsh --resume <id>

重开一个已记录的会话，历史以同样的折叠形态重放。

codsh --continue

接上当前工作区最近的那个会话。

codsh -p "任务"

一次性 print 模式，面向脚本与管道。

DEEPSEEK_API_KEY

模型密钥，从环境变量或 .env 读取。

DSH_HOME

profile 存放位置，默认 ~/.dsh；DSH_BIN 指定启动哪个 dsh。

CODSH_CLIPBOARD

osc52、system 或 off——收窄选中内容进剪贴板的通道。

CODSH_VISION_*

_BASE_URL、_MODEL、_API_KEY：供纯文本模型识图的 OpenAI 兼容 sidecar。不配也行，DeepSeek 文本路由会自动借用 deepseek-v4-flash-vision-exp。

完全不想要启动器？它包装的那两行可以直接用，profile 名任取：

不用启动器
$ dsh plugin --profile code add codsh-bundle
$ dsh --profile code
要动手改？pnpm install && pnpm run dev 在 .dev-home 里维护一份仓库本地的 dsh home，改动几秒钟就能进到运行中的界面； MOCK=markdown pnpm run dev 不需要 key。pnpm run test:e2e 把整棵树打包装进真实 profile 去驱动已发布的二进制——上面每一屏都是这套装置抓的。 codsh 绝不 fork harness：上游的事去 deepseek-harness 提 PR， pnpm run sync:dsh 跟踪它的发布。细节见 README。
